v1.0 · Firebase-like Backend in Go

Apa itu Firego?

Firego adalah backend self-hosted mirip Firebase, ditulis dalam Go. Setiap App memiliki layanan terisolasi: Auth, Database, Storage, Realtime Stream, Remote Config, dan Security Rules.

Base URL : http://localhost:8080 Client API : /v1/{appID}/... Admin API : /admin/... (butuh Admin Key) Health : GET /healthz
Admin Key tampil di terminal saat server start. Simpan di kolom "Admin Key" di header console.

Autentikasi Request

Endpoint client yang membutuhkan auth menerima JWT Bearer token:

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Endpoint admin menerima Admin Key via header:

Authorization: Bearer <admin-key> // atau X-Admin-Key: <admin-key>

Format Response

Semua response berformat JSON. Error dikembalikan dengan field error:

// Sukses { "user": { ... }, "token": "eyJ..." } // Error { "error": "invalid or expired token" }

Rate Limiting

Endpoint auth (/auth/register, /auth/login) dibatasi 10 request/menit per IP. Respon 429 jika melebihi batas.

Multi-App

Setiap app memiliki data, user, token, dan secret JWT yang sepenuhnya terisolasi. Token dari app A tidak berlaku di app B.

Mendapatkan SDK Config

Endpoint publik untuk mendapatkan konfigurasi inisialisasi app. Gunakan ini di client sebelum melakukan request lain.

GET/v1/{appID}/config
// Response { "appId": "default", "name": "Default App", "apiKey": "a3f9c2...", // identitas app untuk client "authDomain": "http://host/v1/default/auth", "databaseURL": "http://host/v1/default/db", "storageBucket": "http://host/v1/default/storage", "streamURL": "http://host/v1/default/stream", "createdAt": 1718000000 }
Tidak perlu autentikasi. apiKey adalah identifier app — berbeda dengan Admin Key.

Contoh Penggunaan (JavaScript)

const cfg = await fetch('/v1/default/config').then(r => r.json()) console.log('DB URL:', cfg.databaseURL) console.log('API Key:', cfg.apiKey)

Register

POST/v1/{appID}/auth/register
// Request Body { "email": "user@example.com", "password": "rahasia123" } // Response 201 { "user": { "uid": "abc123", "email": "user@example.com" }, "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }
Password minimal 8 karakter. Email harus unik per app. Rate limit 10 req/menit per IP.

Login

POST/v1/{appID}/auth/login
// Request Body { "email": "user@example.com", "password": "rahasia123" } // Response 200 { "user": { "uid": "abc123", "email": "user@example.com" }, "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

Logout

POST/v1/{appID}/auth/logout
// Header: Authorization: Bearer {token} // Response 200 { "logged_out": true }
Logout menginvalidasi token di server (blacklist JWT). Token tidak bisa dipakai lagi meski belum expired.

Info User Saat Ini

GET/v1/{appID}/auth/me
// Header: Authorization: Bearer {token} // Response 200 { "user": { "uid": "abc123", "email": "user@example.com" } }

Keamanan Auth

• Password di-hash dengan bcrypt cost 12
• JWT menggunakan HMAC-SHA256 dengan secret unik per app
• Klaim jti untuk token revocation (blacklist in-memory)
• Anti-user-enumeration: waktu respons login sama meski user tidak ada

Struktur Data

Database berupa JSON tree. Setiap node diakses via path seperti /users/alice/profile. Data tersimpan di disk dan disinkronkan ke subscriber SSE secara realtime.

Semua operasi tulis membutuhkan autentikasi. Akses dikontrol oleh Security Rules.

Baca Data

GET/v1/{appID}/db/{path}
// Contoh: GET /v1/default/db/users/alice // Response 200 { "name": "Alice", "age": 28 } // Jika tidak ditemukan → null

Tulis / Replace

PUT/v1/{appID}/db/{path}
// Header: Authorization: Bearer {token} // Body: nilai JSON apa pun (object, array, string, number, bool, null) { "name": "Alice", "age": 28 } // Response 200 → nilai yang disimpan

Update Sebagian (Merge)

PATCH/v1/{appID}/db/{path}
// Hanya field yang dikirim yang diperbarui, field lain tetap { "age": 29 } // Response 200 → field yang diupdate

Push (Auto-Key)

POST/v1/{appID}/db/{path}
// Membuat child baru dengan key unik berurutan (Firebase Push ID) { "text": "Pesan baru", "ts": 1718000000 } // Response 201 { "name": "-Ns7K2qMjAbcDeFgHiJ" } // key yang dibuat

Hapus

DEL/v1/{appID}/db/{path}
// Header: Authorization: Bearer {token} // Response 200 { "deleted": true }

Aturan Path

Segmen path boleh mengandung huruf, angka, underscore, tanda hubung, dan titik. Tidak boleh ada .. atau segmen kosong.

Subscribe Perubahan Data

Gunakan Server-Sent Events (SSE) untuk mendapatkan update realtime saat data berubah.

GET/v1/{appID}/stream/{path}
Snapshot awal langsung dikirim saat connect. Keepalive dikirim tiap 30 detik.

Tipe Event

event: put → data ditulis/direplace (PUT) event: patch → data diupdate sebagian (PATCH) event: delete → data dihapus (DELETE)

Format Data Event

event: put data: {"type":"put","path":"/messages/-Ns7K2qM","data":{"text":"Halo!"}}

Contoh JavaScript

const es = new EventSource('/v1/default/stream/messages') es.addEventListener('put', e => { const { path, data } = JSON.parse(e.data) console.log('PUT', path, data) }) es.addEventListener('patch', e => { const { path, data } = JSON.parse(e.data) console.log('PATCH', path, data) }) es.addEventListener('delete', e => { const { path } = JSON.parse(e.data) console.log('DELETE', path) }) es.onerror = () => console.warn('Stream terputus, browser akan retry...') // Berhenti listen es.close()
Browser otomatis retry SSE jika koneksi putus. Akses stream dikontrol oleh Security Rules — path tanpa izin read akan ditolak dengan 403.

Upload File

POST/v1/{appID}/storage/{name}
// Header: Authorization: Bearer {token} // Header: Content-Type: image/png (atau tipe file Anda) // Body : binary file content // Response 201 { "name": "foto/avatar.png", "contentType": "image/png", "size": 204800, "uploadedAt": 1718000000 }
Ukuran maksimum upload: 100 MiB. Nama file dengan / otomatis membuat struktur folder.

Download File

GET/v1/{appID}/storage/{name}
// Response: binary file dengan Content-Type sesuai file

List Objek

GET/v1/{appID}/storage
// Query param opsional: ?prefix=foto/ // Response 200 { "objects": [ { "name": "foto/avatar.png", "contentType": "image/png", "size": 204800, "uploadedAt": 1718000000 } ] }

Hapus Objek

DEL/v1/{appID}/storage/{name}
// Header: Authorization: Bearer {token} // Response 200 { "deleted": true }

Contoh Upload (JavaScript)

const file = document.querySelector('input[type=file]').files[0] const res = await fetch('/v1/default/storage/foto/avatar.png', { method: 'POST', headers: { 'Authorization': 'Bearer ' + token, 'Content-Type': file.type }, body: file }) const obj = await res.json() console.log('Tersimpan:', obj.name)

Apa itu Remote Config?

Remote Config adalah key-value store per app yang bisa diubah admin kapan saja tanpa deploy ulang. Client membacanya saat startup untuk mendapatkan konfigurasi terkini (feature flags, pesan, threshold, dsb.).

Baca Config (Client)

GET/v1/{appID}/remote-config
// Tidak perlu autentikasi // Response 200 { "maintenance_mode": false, "welcome_message": "Selamat datang!", "max_upload_mb": 10, "feature_dark_mode": true }

Baca Config (Admin)

GET/admin/apps/{appID}/remote-config
// Header: X-Admin-Key: {admin-key} // Response 200 → semua parameter saat ini

Replace Semua Parameter (Admin)

PUT/admin/apps/{appID}/remote-config
// Header: X-Admin-Key: {admin-key} // Body: object JSON baru (mengganti seluruh config) { "maintenance_mode": false, "welcome_message": "Halo!" } // Response 200 { "updated": true }

Merge / Update Sebagian (Admin)

PATCH/admin/apps/{appID}/remote-config
// Hanya key yang dikirim yang diupdate, key lain tetap { "maintenance_mode": true } // Response 200 { "updated": true }

Hapus Satu Key (Admin)

DEL/admin/apps/{appID}/remote-config/{key}
// Response 200 { "deleted": true }

Contoh Penggunaan di Client

// Ambil config saat startup const cfg = await fetch('/v1/default/remote-config').then(r => r.json()) if (cfg.maintenance_mode) { showMaintenanceBanner(cfg.welcome_message) } if (cfg.feature_dark_mode) { document.body.classList.add('dark')

Format Rules

Rules ditulis sebagai JSON tree. Setiap node bisa memiliki .read dan/atau .write berupa ekspresi string.

{ "rules": { ".read": "ekspresi_boolean", ".write": "ekspresi_boolean", "nama_child": { ".read": "ekspresi_lain", "$variable": { ".read": "auth.uid === $variable", ".write": "auth.uid === $variable" } } } }

Ekspresi yang Didukung

true / false → nilai literal auth != null → user sudah login auth == null → user belum login auth.uid → UID user saat ini auth.email → email user saat ini $variable → segment path wildcard 'string' → nilai string literal && || ! → operator logika === !== == != → operator perbandingan

Contoh: Default (Auth Required)

{ "rules": { ".read": "auth != null", ".write": "auth != null" } }

Contoh: Public Read, Auth Write

{ "rules": { ".read": "true", ".write": "auth != null" } }

Contoh: Per-User Data

{ "rules": { ".read": "false", ".write": "false", "users": { "$uid": { ".read": "auth.uid === $uid", ".write": "auth.uid === $uid" } } } }

Contoh: Chat Publik

{ "rules": { ".read": "true", "messages": { ".write": "auth != null" } } }

Aturan Warisan (Cascade)

Jika parent memberikan akses true, semua child path otomatis mendapat akses yang sama — tidak bisa dicabut oleh rule child. Ini sama persis dengan perilaku Firebase.

Default rules: .read dan .write = "auth != null". Ekspresi yang tidak dikenali → deny (false).

Update Rules (Admin)

GET/admin/apps/{appID}/rules
PUT/admin/apps/{appID}/rules
// PUT Body: JSON rules baru // Response: { "updated": true }

List Semua App

GET/admin/apps
// Header: X-Admin-Key: {admin-key} // Response 200 { "apps": [ { "id": "default", "name": "Default App", "apiKey": "...", "createdAt": 1718000000 }, { "id": "my-app", "name": "My App", "apiKey": "...", "createdAt": 1718001000 } ] }

Buat App Baru

POST/admin/apps
// Header: X-Admin-Key: {admin-key} // Body: { "id": "my-app", "name": "My Application" } // Response 201 { "id": "my-app", "name": "My Application", "apiKey": "...", "createdAt": 1718000000 } // ID Rules: 3-30 karakter, huruf kecil/angka/tanda-hubung, awali huruf/angka

Detail App

GET/admin/apps/{appID}
// Response 200 → Info app (id, name, apiKey, createdAt)

Hapus App

DEL/admin/apps/{appID}
// App "default" tidak bisa dihapus (403 Forbidden) // Response 200 { "deleted": true }
Menghapus app akan menghapus SEMUA data: user, database, storage, rules, remote config. Tidak bisa di-undo.

Isolasi Antar App

Setiap app memiliki:

data/apps/{appID}/ ├── users.json ← user auth ├── database.json ← JSON tree database ├── storage/ ← file storage ├── rules.json ← security rules └── remote_config.json ← remote config params

JWT secret per app diturunkan dari master secret via HMAC-SHA256(masterSecret, "firego-app:" + appID) — token antar app tidak saling berlaku.
